# TRI — frontend

Платформа для текстовых ролевых игр. Nuxt 4 + Vue 3 + Pinia, SSR.

## Что нового в этой версии

- **Полная игровая комната `/games/[id]`** с реалтайм-чатом через WebSocket
- **Списки игр** `/games` (все + мои)
- **Создание игры** `/games/new` (создатель = мастер, генерится invite_code)
- **Присоединение по коду** `/games/join` (с выбором персонажа и роли)
- **Composable `useGameWS`** — обёртка над WebSocket, автополучение токена, autoreconnect-логика
- **Типы под актуальный бэк**: `kind`, `action_data`, `event_data` для постов; `participants` с персонажами и силой
- **Форма создания персонажа** с слайдером силы 1-20
- **Server-route `/api/auth/ws-token`** — отдаёт текущий access из HttpOnly-куки в JSON для подключения к WebSocket

## Зависимости

- Node.js 20+
- Запущенный TRI-backend на `http://127.0.0.1:8000` (REST + WebSocket на одном порту)

## Запуск

```bash
npm install
npm run dev
```

Открой `http://localhost:3000`.

## Архитектура

### Поток данных

```
Клиент (браузер)
  │
  ├── REST: $fetch('/api/...') → nitro server-route → apiFetch с Bearer-токеном
  │       (токен в HttpOnly-куке, недоступен JS-клиенту)
  │
  └── WebSocket: new WebSocket('ws://127.0.0.1:8000/ws/games/<id>/?token=<JWT>')
          (напрямую к Django, минуя nitro — он не пропускает живые WS-соединения)
          (токен берётся через GET /api/auth/ws-token который читает HttpOnly-куку)
```

### Зачем такое разделение

- **REST через nitro-прокси** — токены в HttpOnly-куках, недоступных JS, защита от XSS
- **WS напрямую из браузера** — потому что nitro не может держать живой WebSocket: server-route выполняется только на время рендера страницы. WebSocket нужен на всё время жизни страницы, поэтому идёт от клиента к Django

## Структура страниц

```
/                       — лендинг (для незалогиненных и для всех)
/login, /registration   — формы входа/регистрации
/games                  — список игр (все / мои)
/games/new              — создать игру
/games/join             — присоединиться по invite_code
/games/<id>             — комната игры (реалтайм-чат)
/profile, /profile/<id> — профили
/characters/charForm    — создать персонажа (с полем силы)
```

## Игровая комната `/games/[id]`

Три зоны:
- **Шапка**: название, статус, invite_code (видит только мастер), кнопки "Запустить"/"Завершить" (мастер), индикатор онлайн
- **Левая колонка**: участники с ролями, персонажами и силой; зелёная точка — онлайн
- **Центр**: лента постов с разной отрисовкой по `kind`:
  - `chat` — белая карточка с именем персонажа
  - `event` — жёлтая с «Событие · мастер X», блок с NPC если есть
  - `action` — карточка с действием + плашка успех/провал
  - `system` — бейдж по центру: «Алиса (сила 15) одолел(а) Волк (сила 12)»
- **Composer (внизу)**: переключатель режима (Реплика / Действие / Событие — для мастера), для action — выбор цели (NPC / другой игрок / без цели)

## Как работает WS

```ts
// app/composables/useGameWS.ts
const ws = useGameWS(gameId)
await ws.connect(initialPosts)   // подключение
ws.posts        // ref<Post[]>     — все посты, в т.ч. история
ws.online       // ref<Set<number>> — кто онлайн
ws.connected    // ref<boolean>    — подключён ли socket
ws.error        // ref<string | null> — фатальная ошибка
ws.lastError    // ref<string | null> — ошибка от сервера (например, "только мастер")

ws.sendChat('Привет', characterId)
ws.sendAction('Атакую волка', characterId, { kind: 'npc', name: 'Волк', strength: 12 })
ws.sendAction('Атакую боба', characterId, { kind: 'character', id: 5 })
ws.sendAction('Иду по лесу', characterId)  // без цели
ws.sendEvent('Появился волк', { name: 'Волк', strength: 12 })  // только GM
ws.endGame()    // только GM
ws.disconnect()
```

## Сценарий тестирования end-to-end

1. **Регистрируем мастера** (`master` / `SuperSecure123`) → `/registration`
2. Создаём игру `/games/new` → видим invite_code
3. **В другом браузере / приватной вкладке** регистрируем игрока (`alice`)
4. Под `alice` создаём персонажа: `/profile` → "Создать" → имя, сила 15
5. Под `alice` идём `/games/join`, вставляем invite_code, выбираем персонажа → попадаем в игру
6. Под `master` запускаем игру (кнопка "Запустить") — статус становится "Активна"
7. Под `master` создаём событие: режим "Событие" → NPC name="Волк" strength=12 → "В пещере появился волк"
8. Под `alice` действие: режим "Действие" → "Против NPC" → name="Волк" strength=12 → "Атакую волка" → видим успех в обоих окнах
9. Под `alice` действие против Дракона силой 18 → видим провал
10. Реплика от лица персонажа в обычном чате
11. Мастер завершает игру

## Известные ограничения

- WebSocket подключается к `http://127.0.0.1:8000` — этот адрес зашит в `nuxt.config.ts` в `runtimeConfig.public.apiBase`. Если бэк на другом адресе/домене — поменять там.
- В `ALLOWED_HOSTS` Django нужно иметь `localhost` и `127.0.0.1` (уже есть). Если фронт работает с другого домена/порта — добавь туда.
- `auth`-плагин дёргает `/api/auth/me` при старте каждой страницы. Если бэк не отвечает — пользователь будет залогинен как null.
